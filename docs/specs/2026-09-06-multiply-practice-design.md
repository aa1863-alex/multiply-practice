## 背景與目的

給學生（平板上使用）練習九九乘法表的網頁。可以指定要練習哪些倍數（例如 2 的倍數、7 的倍數），一次出一題，答錯的題目會排入下一輪重考，直到全部答對為止。全程用點選作答，不需要鍵盤。

## 技術架構

- 純 HTML + CSS + JavaScript 單頁應用（無 React/Vue、無建置工具、無框架依賴）。
- 所有邏輯在瀏覽器端執行，無後端、無資料庫、無 API。
- 使用 `localStorage` 記住學生上次的設定（選了哪些倍數、題數、作答模式），下次打開網頁自動帶入。
- 檔案結構：
  ```
  multiply-practice/
  ├── index.html
  ├── style.css
  ├── app.js
  ├── docs/specs/2026-09-06-multiply-practice-design.md
  ├── .gitignore
  └── README.md
  ```

## 畫面一：設定畫面

- **倍數選擇**：顯示 **2~9** 的數字按鈕（不含 1，長方形小方格，只比數字本身稍大），可**多選**（例如同時選 2 和 7）。選了哪些數字，之後出題就只從「該數字 × 2~9」的組合中抽題（例如選 2 → 只會出現 2×2 ~ 2×9，不會出現 1×2、3×2 這種反過來的形式，也不會出現 2×1 這種乘 1 的題目）。
- **題數設定**：一個數字輸入框，預設 10，可自行調整。
- **作答模式切換**：兩個選項按鈕—
  - 「數字鍵盤」：作答時顯示 0~9 大按鈕 + 清除 + 確認，讓學生逐位點出答案（支援 1~81 兩位數答案）。
  - 「四選一」：作答時顯示 4 個數字按鈕（1 個正確答案 + 3 個干擾選項，隨機排列）。
- **作答秒數限制**：一個核取方塊「限制每次作答的秒數」，預設**不勾選**（不限秒數）；勾選後旁邊的秒數輸入框才能編輯（預設 10 秒，可自行調整）。
- 「開始練習」按鈕：至少選 1 個倍數才能開始，否則按鈕停用並提示；點擊後不會直接進入練習，而是先進入「畫面二：乘法表複習畫面」。
- 進入複習畫面前，將這次設定（倍數清單、題數、作答模式）存入 `localStorage`。

## 畫面二：乘法表複習畫面

- 左上角有「← 回首頁」按鈕，可隨時返回設定畫面。
- 針對每一個選定的倍數，各顯示一張小卡片，列出該倍數 ×2 ~ ×9 的完整乘法表（例如同時選 3 和 5，就並排顯示「3 的乘法表」「5 的乘法表」兩張卡片）。
- 卡片用響應式網格排列，選的倍數越多，卡片自動換行排列，確保容納得下；反之選的倍數越少，卡片跟文字會依「密度」自動放大，避免只選 1~2 個或 3~4 個倍數時字級顯得太小：
  - 選 1~2 個倍數：每張卡片最寬（`minmax(220px, 1fr)`），標題與表格文字明顯放大。
  - 選 3~4 個倍數：中等放大（`minmax(170px, 1fr)`）。
  - 選 5 個以上倍數：維持原本較密集的版面（`minmax(130px, 1fr)`）。
- 畫面最下方有「我準備好了，按了再開始」按鈕，按下才會真正建立題目、進入畫面三開始作答。

## 畫面三：練習畫面

- 左上角同樣有「← 回首頁」按鈕，可隨時中止練習返回設定畫面。
- **一次只顯示一題**，題目文字用大字級顯示（用 `clamp()` 依視窗寬度縮放字體，確保在平板上非常大、清楚易讀），格式如「2 × 7 = ?」。
- 畫面上方顯示目前進度，例如「第 3 題 / 10 題（第 1 輪）」。
- 若設定了秒數限制，題目下方顯示倒數「剩餘時間：X 秒」，剩餘 ≤3 秒時變紅色提醒。
- **作答互動**（依設定選擇其中一種模式呈現）：
  - 數字鍵盤模式：點選數字組成答案顯示在暫存區（字級加大、顏色為**深藍色**，與題目文字的深色區隔），可點清除重來，點確認送出；數字鍵盤按鈕本身字級也加大。鍵盤版面：1~9 為 3×3 排列，「0」在第 4 排最左格，「清除」緊接在 0 右邊、橫跨後兩格（跟 8、9 對齊），「確認」則獨立佔滿一整排在鍵盤下方，厚度（短邊）與「清除」鍵對齊一致。
  - 四選一模式：點選其中一個選項即視為送出答案；四個選項數字字級大幅加大。
- **作答回饋**：
  - 送出答案後立即用顏色標示對（綠）或錯（紅）的提示文字（「答對了！」/「這次對了！」）。
  - **答對時**：同時也在題目等號後面顯示正確答案，用藍色（例如「6 × 8 = 48」，48 為藍字），跟提示文字一起保留；畫面停留 1 秒後自動換下一題。
  - 若第一次答錯（或秒數限制下第一次逾時未作答）：允許**立刻重新作答一次**（同一題），秒數限制開啟時會為這次重試重新倒數。
  - 若第二次仍答錯或逾時：**直接在題目的等號後面揭曉正確答案**，例如「6 × 5 = 30」，其中「30」用紅字顯示；同時（數字鍵盤模式下）清空暫存區裡原本錯誤的答案，避免跟紅字正解混在一起；畫面停留 3 秒後才自動換下一題（比其他情況的切換間隔更長，讓學生看清楚正確答案）。四選一模式採用同樣的處理方式。
  - **判定規則**：只要這一題不是「第一次就答對」，無論後面有沒有補答對，這一題都算「錯」，會被排入下一輪重考清單。
- 全部按鈕皆為大尺寸觸控目標，不出現任何文字輸入框或呼叫系統鍵盤。

## 重考邏輯（跨輪次）

- 第 1 輪：從選定倍數的題目池中隨機抽出設定的題數（預設 10 題）。
- 每一輪結束後：
  - 若這一輪沒有任何錯題 → 視為練習完成，進入完成畫面。
  - 若有錯題 → 建立下一輪題目：**題數為錯題數的兩倍**——全部錯題 + 等量（與錯題數相同的數量）從**這一輪答對的題目**中隨機抽取的題目補滿（例如錯 1 題 → 下一輪 2 題；錯 2 題 → 下一輪 4 題）。若這一輪全部答錯（沒有答對過的題目可抽），則改從整個題目池中隨機抽取來補滿。
- 重複上述流程，直到某一輪「全對」為止。
- 此規則從第 2 輪起生效，且往後每一輪都套用同樣的「錯題數 × 2」規則，題數會隨錯題狀況動態增減，不再固定等於設定的題數。

## 畫面四：完成畫面

- 顯示恭喜訊息。
- **得分**：把「第一次就答對的題數 / 總作答題數」乘上 100，四捨五入成 0~100 的分數，例如「80 分」。用大字級、紅色、粗體顯示，做出類似考試分數／遊戲得分的視覺效果。
- 顯示統計：總共花了幾輪、總作答次數。
- 「再練習一次」按鈕：回到設定畫面（沿用上次設定或允許重新選擇）。

## 部署流程

程式碼一樣維護在 GitHub repo `aa1863-alex/multiply-practice`（`git push` 保留版本歷史），但**實際上線**改回**直接用 `wrangler deploy` 部署**：

1. 原本計畫是 GitHub 連接 Cloudflare 自動部署，但 2026-09-06 實測發現使用者在 Cloudflare Dashboard 建立的其實是 **Cloudflare Workers**（不是 Pages）的一次性匯入，並沒有接上真正的 Git 持續部署（GitHub repo 沒有 webhook，Worker 也沒有 Builds/Git 設定）。第二次 `git push` 之後線上內容完全沒有更新，才發現這個問題。
2. 因此改成：程式碼還是 push 到 GitHub 留存歷史，但每次要讓網站更新時，另外在 `/Users/klscratch1/multiply-practice` 執行 `npx wrangler deploy` 直接部署最新程式碼到既有的 Worker `multiply-practice`。
3. 專案根目錄有 `wrangler.toml`（宣告成純靜態資源的 Worker，`[assets] directory = "."`）與 `.assetsignore`（排除 `.git`、`.wrangler`、`docs`、`wrangler.toml`、`README.md` 等非網站本體檔案，避免被一起部署上去）。
4. 網站網址：`https://multiply-practice.aa1863.workers.dev`，以及使用者自訂的網域 `https://99.smartchu321.win`（皆指向同一個 Worker）。

## 不在範圍內（YAGNI）

- 不做使用者帳號、不做多人/雲端進度同步。
