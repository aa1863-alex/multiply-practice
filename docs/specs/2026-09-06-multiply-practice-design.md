## 背景與目的

給學生（平板上使用）練習九九乘法表的網頁。可以指定要練習哪些倍數（例如 2 的倍數、7 的倍數），一次出一題，答錯的題目會排入下一輪重考，直到全部答對為止。全程用點選作答，不需要鍵盤。

## 技術架構

- 純 HTML + CSS + JavaScript 單頁應用（無 React/Vue、無建置工具、無框架依賴）。
- 所有邏輯在瀏覽器端執行，無後端、無資料庫、無 API。
- 使用 `localStorage` 記住學生上次的設定（選了哪些倍數、題數、作答模式），下次打開網頁自動帶入。
- 檔案結構：
  ```
  multiply-practice/
  ├── index.html
  ├── style.css
  ├── app.js
  ├── docs/specs/2026-09-06-multiply-practice-design.md
  ├── wrangler.toml
  ├── .assetsignore
  ├── .gitignore
  └── README.md
  ```

## 畫面一：設定畫面

- **右上角音效開關**：右上角一個小巧的勾選框「音效」，**預設打勾**（開啟），不需要另外的說明文字；打勾時答對／答錯才會播放提示音（見下方作答回饋一節）。用瀏覽器內建 Web Audio API 即時合成音效，不需要外部音檔案。
- **倍數選擇**：顯示 **2~9** 的數字按鈕（不含 1，長方形小方格，只比數字本身稍大），可**多選**（例如同時選 2 和 7）。選了哪些數字，之後出題就只從「該數字 × 2~9」的組合中抽題（例如選 2 → 只會出現 2×2 ~ 2×9，不會出現 1×2、3×2 這種反過來的形式，也不會出現 2×1 這種乘 1 的題目）。
- **題數**與**作答時間限制**並排在同一水平線上（兩欄各佔一半寬）：
  - 「題數」：兩個選項按鈕「自訂題數」／「全部題目」。選「自訂題數」時顯示數字輸入框（預設 10，可自行調整）；選「全部題目」時改顯示「全部題目共 N 題」的提示文字（N 依目前選定的倍數即時計算，即該倍數池 ×2~×9 的組合數，例如選 2 和 5 兩個倍數 → 2×8=16 題），不顯示輸入框。「全部題目」模式下，第 1 輪就是把整個題目池洗牌後全部出一次（不重複抽樣），之後輪次仍照下方的重考邏輯進行。
  - 「作答時間限制」：勾選框在標題文字「作答時間限制」的左邊（同一行），下方是秒數輸入框；勾選框**預設不勾**（不限秒數），不勾時秒數輸入框停用；不再額外顯示「限制每次作答的秒數」這句說明文字，靠標題本身就能理解用途。
- **作答模式切換**：兩個選項按鈕—
  - 「數字鍵盤」：作答時顯示 0~9 大按鈕 + 清除 + 確認，讓學生逐位點出答案（支援 1~81 兩位數答案）。
  - 「四選一」：作答時顯示 4 個數字按鈕（1 個正確答案 + 3 個干擾選項，隨機排列）。
- 「開始練習」按鈕：至少選 1 個倍數才能開始，否則按鈕停用並提示；點擊後不會直接進入練習，而是先進入「畫面二：乘法表複習畫面」。
- 進入複習畫面前，將這次設定（倍數清單、題數、作答模式、音效、秒數限制）存入 `localStorage`。

## 畫面二：乘法表複習畫面

- 左上角有「← 回首頁」按鈕，可隨時返回設定畫面。
- 針對每一個選定的倍數，各顯示一張小卡片，列出該倍數 ×2 ~ ×9 的完整乘法表（例如同時選 3 和 5，就並排顯示「3 的乘法表」「5 的乘法表」兩張卡片）。
- 卡片用響應式網格排列，選的倍數越多，卡片自動換行排列，確保容納得下；反之選的倍數越少，卡片跟文字會依「密度」自動放大，避免只選 1~2 個或 3~4 個倍數時字級顯得太小：
  - 選 1~2 個倍數：每張卡片最寬（`minmax(220px, 1fr)`），標題與表格文字明顯放大。
  - 選 3~4 個倍數：中等放大（`minmax(170px, 1fr)`）。
  - 選 5 個以上倍數：維持原本較密集的版面（`minmax(130px, 1fr)`）。
- 畫面最下方有「我準備好了，按了再開始」按鈕，按下才會真正建立題目、進入畫面三開始作答。

## 畫面三：練習畫面

- 左上角同樣有「← 回首頁」按鈕，可隨時中止練習返回設定畫面。
- **一次只顯示一題**，題目文字用大字級顯示（用 `clamp()` 依視窗寬度縮放字體，確保在平板上非常大、清楚易讀），格式如「2 × 7 = ?」。
- 畫面上方顯示目前進度，例如「第 3 題 / 10 題（第 1 輪）」。
- 若設定了秒數限制，題目下方顯示倒數「剩餘時間：X 秒」，剩餘 ≤3 秒時變紅色提醒。
- **作答互動**（依設定選擇其中一種模式呈現）：
  - 數字鍵盤模式：點選數字組成答案顯示在暫存區（字級加大、顏色為**深藍色**，與題目文字的深色區隔），可點清除重來，點確認送出；數字鍵盤按鈕本身字級也加大。鍵盤版面：1~9 為 3×3 排列，「0」在第 4 排最左格，「清除」緊接在 0 右邊、橫跨後兩格（跟 8、9 對齊），「確認」則獨立佔滿一整排在鍵盤下方，厚度（短邊）與「清除」鍵對齊一致。
  - 四選一模式：點選其中一個選項即視為送出答案；四個選項數字字級大幅加大。
- **作答回饋**：
  - 送出答案後立即用顏色標示對（綠）或錯（紅）的提示文字（「答對了！」/「這次對了！」），若音效開啟則同時播放提示音——答對是上揚的兩音提示音，答錯（含逾時）是低沉的提示音。
  - **答對時**：同時也在題目等號後面顯示正確答案，用藍色（例如「6 × 8 = 48」，48 為藍字），跟提示文字一起保留；畫面停留 1 秒後自動換下一題。
  - 若第一次答錯（或秒數限制下第一次逾時未作答）：允許**立刻重新作答一次**（同一題），秒數限制開啟時會為這次重試重新倒數。
  - 若第二次仍答錯或逾時：**直接在題目的等號後面揭曉正確答案**，例如「6 × 5 = 30」，其中「30」用紅字顯示；同時（數字鍵盤模式下）清空暫存區裡原本錯誤的答案，避免跟紅字正解混在一起；畫面停留 3 秒後才自動換下一題（比其他情況的切換間隔更長，讓學生看清楚正確答案）。四選一模式採用同樣的處理方式。
  - **判定規則**：只要這一題不是「第一次就答對」，無論後面有沒有補答對，這一題都算「錯」，會被排入下一輪重考清單。
- 全部按鈕皆為大尺寸觸控目標，不出現任何文字輸入框或呼叫系統鍵盤。
- **橫向（landscape）版面**：偵測到裝置為橫向時（例如 iPad 橫擺），練習畫面改成左右並排——左邊放題目資訊（回首頁按鈕、進度、題目、倒數、回饋文字），右邊放作答區（數字鍵盤或四選一），字級改用 `vh`（視窗高度）為基準的 `clamp()` 縮放，確保橫向時因為高度變矮，畫面不會被切掉或需要滾動才能看到確認鍵。直向（portrait）時維持原本上下堆疊的版面不變。

## 重考邏輯（跨輪次）

- 第 1 輪：從選定倍數的題目池中隨機抽出設定的題數（預設 10 題）。
- 每一輪結束後：
  - 若這一輪沒有任何錯題 → 視為練習完成，進入完成畫面。
  - 若有錯題 → 建立下一輪題目：**題數為錯題數的兩倍**——全部錯題 + 等量（與錯題數相同的數量）從**這一輪答對的題目**中隨機抽取的題目補滿（例如錯 1 題 → 下一輪 2 題；錯 2 題 → 下一輪 4 題）。若這一輪全部答錯（沒有答對過的題目可抽），則改從整個題目池中隨機抽取來補滿。
- 重複上述流程，直到某一輪「全對」為止。
- 此規則從第 2 輪起生效，且往後每一輪都套用同樣的「錯題數 × 2」規則，題數會隨錯題狀況動態增減，不再固定等於設定的題數。

## 畫面四：完成畫面

- 顯示恭喜訊息。
- **得分**：把「第一次就答對的題數 / 總作答題數」乘上 100，四捨五入成 0~100 的分數，例如「80 分」。用大字級、紅色、粗體顯示，做出類似考試分數／遊戲得分的視覺效果。
- **常錯的題目**：分數下方顯示一張卡片，列出這次練習中（不限哪一輪）**曾經**答錯過的題目與正確答案，去除重複，依倍數、乘數排序，例如「4 × 8 = 32」，字級明顯放大方便閱讀；若完全沒有錯過任何題目，則不顯示這張卡片。
- 顯示統計：總共花了幾輪、總作答次數。
- 「再練習一次」按鈕：回到設定畫面（沿用上次設定或允許重新選擇）。

## 資料模型（JS 內部）

```js
// 一題
{ a: 2, b: 7, answer: 14 }

// 設定（存入 localStorage，key 為 'multiply-practice-settings'）
{
  multipliers: [2, 7],
  questionCount: 10,
  mode: 'keypad' | 'choice',
  timeLimitEnabled: false,
  timeLimitSeconds: 10,
  soundEnabled: true
}

// 練習狀態
{
  pool: [...題目...],             // 選定倍數 × 2~9 的題目池
  round: 1,
  roundQuestions: [...題目...],   // 這一輪的題目
  index: 0,                       // 目前第幾題
  attempt: 1,                     // 這一題第幾次作答（1 或 2）
  wrongThisRound: [...題目...],   // 這一輪答錯（含補答對也算錯）的題目
  correctThisRound: [...題目...],
  everWrong: Map,                 // 整次練習曾經答錯的題目（去重，key 為 "a-b"），供完成畫面列出
  stats: { totalAsked, totalFirstTryCorrect },
  timerId: null,
  timeLeft: 0
}
```

## 部署流程

程式碼維護在 GitHub repo `aa1863-alex/multiply-practice`，**push 到 `main` 分支即由 Cloudflare Workers Builds 自動部署**。

1. **現行做法（2026-09-10 起）**：在 Cloudflare Dashboard 將 Worker `multiply-practice` 的 Settings → Build 連接此 GitHub repo，設定如下：
   - Build command：留空（純靜態網站，不需建置）
   - Deploy command：`npx wrangler deploy`
   - Version command（非正式分支）：`npx wrangler versions upload`
   - Root directory：`/`
   - Production branch：`main`，並開啟非正式分支建置（產生預覽版本）
   - Build watch paths：include `*`
   - GitHub 端需安裝「Cloudflare Workers and Pages」GitHub App，且 Repository access 必須包含 `multiply-practice`（初次設定時漏勾，導致 push 後完全沒有觸發建置）
2. 因為可能在多台電腦上開發，GitHub 為唯一正本，**不再從本機執行 `npx wrangler deploy`**，避免用未 push 或較舊的程式碼蓋掉線上版本（操作流程見 README「在多台電腦上開發」一節）。
3. 專案根目錄有 `wrangler.toml`（宣告成純靜態資源的 Worker，`[assets] directory = "."`）與 `.assetsignore`（排除 `.git`、`.wrangler`、`docs`、`wrangler.toml`、`README.md` 等非網站本體檔案，避免被一起部署上去）。
4. 網站網址：`https://multiply-practice.aa1863.workers.dev`，以及使用者自訂的網域 `https://99.smartchu321.win`（皆指向同一個 Worker）。
5. **歷史紀錄**：原本計畫是 GitHub 連接 Cloudflare 自動部署，但 2026-09-06 實測發現當時在 Cloudflare Dashboard 建立的是 **Cloudflare Workers**（不是 Pages）的一次性匯入，並沒有接上真正的 Git 持續部署，push 後線上內容沒有更新；因此 2026-09-06 ~ 2026-09-10 期間改為手動在本機執行 `npx wrangler deploy`，直到上述 Workers Builds 設定完成。

## 不在範圍內（YAGNI）

- 不做使用者帳號、不做多人/雲端進度同步。
- 不做除了 ×（乘法）以外的運算（無加減除）。
- 不做動畫特效等額外裝飾（音效已於 2026-09-09 納入範圍，見設定畫面與作答回饋兩節）。
- 不支援反向題目形式（N × 選定數字）。
